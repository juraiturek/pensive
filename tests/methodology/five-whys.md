# 5 Whys methodology verification

The retained `five-whys-observed.json` contains implementation-author synthetic walkthroughs of the actual Markdown creation/action contracts, full inputs and outputs. These are reviewed reference examples, not independent model sampling, statistical evaluations or evidence from live users. No external incident research was executed.

Coverage: rich context with competing causes; adaptive two-turn elicitation and explicit sparse agreement; blank/optional/declined activation; unsupported blame story; plausible branch beyond framing; suspected root needing a diagnostic test; no-addition response when evidence is insufficient; selected-branch Deepen; sibling Branch. The real runtime, Ajv schema and CLI validate/package the retained outputs. Acceptance checks preserve original descendants and unrelated branches.

Review criteria: extract framing before content; label observed/reported/hypothesized material; distinguish plausible mechanism from local proof; examine temporal order and missing intermediates; avoid circular restatements; allow competing/complementary causes; no five-level target; no certainty from closure; investigate discrepancies bidirectionally rather than force content into framing. Research remains explicitly authorized conversational follow-up and must distinguish general evidence from evidence of the local chain.

`five-whys-v2-parity.json` is different evidence: actual outputs of the original V2 helper functions extracted via Python AST without importing the application. The generator is `tests/generate-five-whys-v2-fixtures.py`; normal tests use retained JSON and do not require legacy access. It also renders original Jinja templates/CSS into ignored static fixtures for visual comparison. This verifies helper parity and static geometry; it does not run the legacy application, HTMX, Alpine or its backend tests.

Limits: reference-example quality is reviewed by the implementation author; deterministic checks establish protocol, structural and mutation-boundary behavior, not general causal reasoning ability or correctness of hypotheses. Browser verification is offline Chromium, including desktop/narrow viewports, not physical devices or Safari/Firefox.

A separate `five-whys-agent-observed.json` retains actual synthetic applications by a fresh test actor who read the current methods: reporting-pipeline creation, adaptive sparse elicitation, unsupported blame Reflect, selected input Deepen, processing-sibling Branch and insufficient-evidence no-addition. Full requests/responses and limits are retained. Old HEAD routing was assessed read-only as unsupported; no empirical pre-change failure transcript is claimed. The independent examples are also validated and packaged by the retained test. This adds a narrow independent observation, not a deployed-model benchmark.
